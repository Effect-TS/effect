# Prototype for `specs/tree-shakeable-services.md`

A runnable model of `Context.Operation`, `Stream.Operation`, `Sink.Operation`
and `Context.Operations`. The primitives live in `packages/effect/src/Context.ts`,
`packages/effect/src/Stream.ts` and `packages/effect/src/Sink.ts` on this
branch, and `packages/effect/src/FileSystem.ts` and `Terminal.ts` are record services over operations;
this package exercises the primitives through the public `effect` API and
checks the spec's claims.

| Path                        | What it is                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/FileSystem.ts`         | The file system contract as a consumer sees it, in one module: its error and data types, the thirty operations (each declaring its shape once), the record service `FileSystem` over the written member list with `Shape` and the identity derived from it, and `ReadOnly`, a subset record over three of the members with a shape derived the same way                                                                                                                                |
| `src/Terminal.ts`           | A 6-member contract modelled on `effect/Terminal`: five operations of no arguments and one with a parameter                                                                                                                                                                                                                                                                                                                                                                            |
| `src/NodeFileSystem.ts`     | The Node implementation in one module: one layer per operation as a top-level export, each tagged with a `node/FileSystem/<op>` marker, and `layer`, the thirty merged (a `Layer<FileSystem>` by annotation, the coarse-grained form)                                                                                                                                                                                                                                                  |
| `src/NodeTerminal.ts`       | The same layout for the terminal: six layers and `layer`                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `src/program.ts`            | A program using two of the thirty operations                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `src/program-readonly.ts`   | A program annotated with the `ReadOnly` subset as its one requirement                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `src/program-record.ts`     | A program that yields the whole record                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `src/program-stream.ts`     | A program using one Stream operation                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `src/program-terminal.ts`   | A program calling an operation of no arguments and one with a parameter                                                                                                                                                                                                                                                                                                                                                                                                                |
| `src/program-twenty.ts`     | A program using twenty operations                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `src/main*.ts`              | One composition root per program (and `main-full.ts`: the two-operation program on the record)                                                                                                                                                                                                                                                                                                                                                                                         |
| `test/Operation.test.ts`    | Runtime semantics: provision, overrides, lookup timing, Streams, Sinks, receivers, record storage (one overlay per member, a member override as an overlay, the record read as a plain object of the members with the same keys through overlays and a flat map, a class instance with bound methods), nested and subset records, a record never written, and "same string, same key" (a duplicate key object, a `Context.Service` with a member's string, a record constructed twice) |
| `typetest/ok/signatures.ts` | Type assertions that must compile                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `typetest/errors/*.ts`      | One file per type error the design relies on                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `scripts/check-errors.ts`   | Compiles `typetest/errors`, prints the diagnostics, and checks each file fails as documented                                                                                                                                                                                                                                                                                                                                                                                           |
| `scripts/check-bundle.ts`   | The bundle check: esbuild (and Rolldown) on every root, with `effect` and the four library modules above bundled as published, the implementations each bundle carries out of the one provider module (by marker and by bytes), the Stream-runtime byte count, and the annotation matrix for the contract and the provider as written, annotated by hand, and published                                                                                                                |
| `scripts/bench-check.ts`    | The cost gate in three modes: `counts.ts --check` (Map, Set and WeakMap operations and bytes per call, which do not depend on load: the gate proper), then the timing benchmark for ordinary keys and for records, each run in three orders of its pairs and gated on the median (ratios against the branch point's `Context.ts`; a noisy A/A control is a SKIPPED result, not a failure, and never stops the next mode)                                                               |
| `pnpm bench`                | Runs `packages/effect/benchmark/context/operations.ts`, the paired timing benchmark (CPU-time ratios, an A/A control whose envelope widens every limit, one retry with more rounds); `--check` enforces the limits, `--ordinary` runs a process that holds no record, `BENCH_ONLY=<text>` runs the pairs whose label contains it. `pnpm bench:counts` runs the counts alone                                                                                                            |

From the repository root, after `pnpm install`:

```sh
pnpm --filter tree-shakeable-services-spec verify
```

runs, in order, `check` (tsc), `check-errors`, `test` (vitest), `bundle`
(esbuild and Rolldown) and `bench:check` (the counts, then the timing
benchmark in both modes and three orders, with its limits enforced; about
fifteen minutes). Each
can be run on its own with the same `--filter`; `bench` prints the timing
tables without enforcing limits.
