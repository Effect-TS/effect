# Argon2 implementation provenance

The portable Argon2id v19 implementation, its BLAKE2b helper, WASM block
compressor, admission design, and known-answer fixtures were ported from
[Yielded Auth](https://github.com/yielded-dev/auth) revision
`1b946d32b4519725307783c42018c072e78a639d` (`packages/crypto`).
The Effect port changes imports, integrates native KDF services and errors,
and adds explicit backend layers; it retains the underlying arithmetic.

The arithmetic was adapted from noble-hashes 2.3.0, revision
`8060cc83bbab6681d23c9eed071db3f3a6b442da`:
`src/argon2.ts`, `src/blake2.ts`, `src/_blake.ts`, and `src/_u64.ts`.
They correspond to `internal/argon2Core.ts`, `internal/blake2b.ts`, and
`internal/word64.ts`. The C compressor expresses the same block operation
using WASM SIMD. No runtime downloads or dynamic code evaluation are used.

All nine Argon2id v19 known answers from noble-hashes `test/argon2.test.ts`
are retained in `test/crypto/fixtures/argon2-vectors.ts`. The RFC 9106 example
also appears in the Argon2 reference suite at
`P-H-C/phc-winner-argon2` revision `f57e61e19229e23c4445b85494dbf7c07de721cb`.
The reference project credits Daniel Dinu, Dmitry Khovratovich,
Jean-Philippe Aumasson and Samuel Neves (2015), and offers CC0-1.0 or
Apache-2.0; the selected vector is used under Apache-2.0. Additional
binary-input, memory-rounding and variable-output fixtures were independently
calculated with Node.js 24.21.0 `crypto.argon2Sync` in the source project.
RFC 7914 scrypt numerical vectors are also exercised. The IETF code component
license is retained below. Attribution does not transfer upstream audits to
this adapted implementation.

## Reproducing the binary import

The checked-in `argon2.wasm` is an immutable import, not hand-edited output.
From a clean checkout of the source revision above, copy exactly:

- `packages/crypto/src/internal/argon2.wasm` to `src/crypto/argon2.wasm`.
- `packages/crypto/src/internal/argon2-block.c` to `src/crypto/internal/argon2Block.c`.

Verify SHA-256 before accepting either file:

```text
75e69fc64647848d2ad32f6c860c569a49ab02389797ccba782e069bcb9cf78e  argon2.wasm
28e77a9ba3eb92bad50d5d4dfb6bd323533b9860a1ffa184929963b379c295fb  argon2Block.c
```

The binary imports only `env.memory` and exports `argon2_block` and
`__heap_base`. `Kdf.layerWasm` receives a precompiled `WebAssembly.Module`;
Workers consumers statically import `effect/crypto/argon2.wasm` through their
bundler. Each derivation owns and wipes its entire linear memory.

The source project's build command, adjusted only for paths, is:

```sh
clang --target=wasm32 -O3 -msimd128 -ffreestanding -fno-builtin -nostdlib \
  -Wl,--no-entry -Wl,--import-memory -Wl,--export=argon2_block \
  -Wl,--export=__heap_base -Wl,--strip-all \
  packages/effect/src/crypto/internal/argon2Block.c \
  -o packages/effect/src/crypto/argon2.wasm
```

A WASM-capable clang and `wasm-ld` are required. The original compiler version
was not recorded upstream, so byte-for-byte reproduction is guaranteed by
the pinned import and digests, not by an unpinned compiler invocation. Future
compiler rebuilds must update the provenance and digest and rerun both
portable and WASM known-answer and cleanup tests.
